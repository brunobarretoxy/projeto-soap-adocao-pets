5. ESTRUTURA DO ENVELOPE SOAP
================================================================================

Exemplo de requisição válida (cadastrarPet):
---
<?xml version="1.0" encoding="UTF-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <tns:cadastrarPet xmlns:tns="urn:pareapet:soap">
      <nome>Rex</nome>
      <especie>Cachorro</especie>
      <porte>Grande</porte>
    </tns:cadastrarPet>
  </soap:Body>
</soap:Envelope>
---

Exemplo de resposta bem-sucedida:
---
<?xml version="1.0" encoding="UTF-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <tns:cadastrarPetResponse xmlns:tns="urn:pareapet:soap">
      <result>
        <id>1</id>
        <nome>Rex</nome>
        <especie>Cachorro</especie>
        <porte>Grande</porte>
        <status>Disponivel</status>
      </result>
    </tns:cadastrarPetResponse>
  </soap:Body>
</soap:Envelope>
---

Exemplo de SOAP Fault (erro):
---
<?xml version="1.0" encoding="UTF-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <soap:Fault>
      <faultcode>Client</faultcode>
      <faultstring>O nome do pet é obrigatório.</faultstring>
    </soap:Fault>
  </soap:Body>
</soap:Envelope>
---

9. JUSTIFICATIVA TÉCNICA - POR QUE SOAP FOI ADEQUADO AO CENÁRIO
================================================================================

SOAP foi escolhido para este serviço de adoção de pets por:

1. INTEROPERABILIDADE: SOAP é independente de linguagem e plataforma. Prova: 
   servidor em Python é consumido com sucesso por cliente Java e Python.

2. CONTRATO FORMAL: O WSDL define explicitamente as operações, tipos e comportamentos,
   eliminando ambiguidades. Clientes podem gerar stubs automaticamente.

3. VALIDAÇÃO FORTE: SOAP permite especificar tipos complexos, campos obrigatórios
   e estrutura rigorosa das mensagens, ideal para garantir dados corretos.

4. TRATAMENTO DE ERROS: SOAP Faults fornecem mecanismo padrão para erros de aplicação,
   com código e mensagem estruturados, sem depender de códigos HTTP.

5. CONTEXTO ACADÊMICO: Este projeto demonstra um protocolo consolidado e maduro,
   apropriado para fins educacionais sobre integração de sistemas.

LIMITAÇÕES COMPARADAS COM REST:
- REST seria mais simples para esta aplicação pequena
- JSON seria mais leve que XML
- Mas SOAP serve melhor ao objetivo pedagógico de aprender interoperabilidade

10. DIFICULDADES TÉCNICAS ENFRENTADAS E SOLUÇÕES
================================================================================

DIFICULDADE 1: Compatibilidade Spyne com Python 3.14
- PROBLEMA: Spyne 2.14.0 não é compatível com Python 3.14 (módulo six.moves faltante)
- SOLUÇÃO: Implementar servidor alternativo usando Flask + lxml diretamente
- RESULTADO: Servidor funcional 100%, sem dependência de Spyne

DIFICULDADE 2: Ausência de Maven no ambiente
- PROBLEMA: Cliente Java original usava Maven para gerar stubs via wsimport
- SOLUÇÃO: Implementar cliente Java simples que constrói requisições SOAP manualmente
- RESULTADO: Cliente Java compilado e testado com sucesso, sem Maven

DIFICULDADE 3: Encoding de caracteres no Windows
- PROBLEMA: Console Windows não suporta UTF-8 diretamente em Python
- SOLUÇÃO: Remover emojis e usar ASCII puro nos testes
- RESULTADO: Output legível em ambos os ambientes
